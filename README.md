# راهنمای راه‌اندازی و کار با سامانه دو‌رباتی

این مجموعه مسیر آماده‌سازی لپ‌تاپ، اتصال به ربات‌ها، اجرای Robot 2 و مشاهده نقشه و گزارش اجرا را توضیح می‌دهد. مخاطب آن دانشجویی است که سامانه را برای نخستین بار راه‌اندازی می‌کند.

مستندات بر Ubuntu 24.04 در WSL 2 و ROS 2 Jazzy تکیه دارند. راه‌اندازی WSL از راهنمای [مایکروسافت](https://learn.microsoft.com/windows/wsl/install/) و نصب ROS از [راهنمای رسمی ROS 2](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html) پیروی می‌کند.

## شروع سریع

۱. در PowerShell، Ubuntu 24.04 را نصب کنید و یک‌بار از منوی Start اجرا کنید تا حساب لینوکس ساخته شود.

~~~powershell
wsl --install -d Ubuntu-24.04
wsl --list --verbose
~~~

۲. پیش از نصب بسته‌ها، پراکسی v2rayN را طبق [راهنمای ویندوز و WSL](docs/01_windows_wsl_setup.md) آماده کنید. نصب‌کننده فعلی این پراکسی را لازم دارد.

۳. پوشه کامل بسته WSL را روی Desktop ویندوز بگذارید. از Ubuntu فایل‌ها را نصب و سپس وابستگی‌ها را دریافت کنید.

~~~bash
bash "/mnt/c/Users/<WindowsUser>/Desktop/<HandoffFolder>/WSL/install_bundle_files.sh"
source ~/.bashrc
bash ~/install_robot_handoff_dependencies.sh
~~~

۴. قالب SSH را بررسی کنید، برای هر ربات یک کلید جدا بسازید و کلید عمومی را روی همان Pi ثبت کنید. هر دو اتصال را پیش از اجرای ربات امتحان کنید.

~~~bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_robot1
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_robot2
ssh-copy-id -i ~/.ssh/id_ed25519_robot1.pub robot1
ssh-copy-id -i ~/.ssh/id_ed25519_robot2.pub robot2
ssh robot1 hostname
ssh robot2 hostname
~~~

اگر ورود اولیه با گذرواژه روی Pi فعال نیست، از مسئول آزمایشگاه روش ثبت کلید را بگیرید. گذرواژه و کلید خصوصی را در مخزن قرار ندهید.

۵. برای ورود Piها به پرتال اینترنت دانشگاه، این فرمان را در WSL اجرا کنید و اطلاعات حساب را هنگام درخواست وارد کنید.

~~~bash
~/robot_wifi_login
~~~

۶. داشبورد جفت‌رباتی را باز کنید و اجرای Robot 2 را آغاز کنید.

~~~bash
~/robot_pair_view
~/robot2_visual
~~~

برای داده‌های Robot 1، فرمان **~/robot1_visual** را اجرا کنید؛ پیش از آن باید راه‌انداز سمت Pi و دسترسی SSH آن تأیید شده باشد. کد Robot 1 در نسخه بررسی‌شده موجود نبود.

فرمان توقف هر ربات را جداگانه اجرا کنید. بستن پنجره داشبورد، RViz یا ترمینال WSL اجرای راه‌دور را متوقف نمی‌کند.

~~~bash
~/robot2_stop
~~~

۷. برای ساخت ویدئو از اجراهای ذخیره‌شده، FFmpeg ویندوز را طبق [راهنمای نصب](docs/01_windows_wsl_setup.md) آماده کنید و سپس اجرا کنید.

~~~bash
~/robot_pair_video
~~~

## فرمان‌های آماده

| فرمان | کاربرد |
|---|---|
| **~/robot1_visual** | اجرای راه‌دور Robot 1 و پل مشاهده WSL |
| **~/robot1_stop** | درخواست توقف Robot 1 |
| **~/robot2_visual** | اجرای راه‌دور Robot 2 و پل مشاهده WSL |
| **~/robot2_stop** | درخواست توقف Robot 2 |
| **~/robot_pair_view** | نمایش نقشه و وضعیت دو ربات روی لپ‌تاپ و تلفن |
| **~/robot_pair_video** | دریافت خروجی‌های نهایی و ساخت ویدئو و گزارش |
| **~/robot_wifi_login** | ورود هر دو Pi به پرتال اینترنت دانشگاه |
| **proxy_on**، **proxy_off**، **proxy_test** | کنترل و بررسی پراکسی WSL |

## دامنه و وضعیت مستندات

شاخه‌ای که این مستندات در آن قرار دارند فقط فایل‌های راهنما را نگه می‌دارد. کد نهایی ربات‌ها و بسته WSL هنوز در آن منتشر نشده‌اند. این مجموعه برای آماده‌سازی کامل Pi از نصب سیستم‌عامل تا اجرای ROS کافی نیست.

نسخه پشتیبان Robot 2 در پوشه‌ای با نام **robot1** قرار دارد. این نام از محیط قبلی Pi به ارث رسیده و نشان‌دهنده کد Robot 1 نیست. کد معتبر Robot 1 در فایل‌های بررسی‌شده نبود.

پیش از تحویل اجرایی، باید نسخه کد WSL و Robot 1، تصویر و نسخه سیستم‌عامل Pi، وابستگی‌های ساخت، نقشه سیم‌کشی و روش‌های تکرارپذیر کالیبراسیون به این مجموعه افزوده شوند. اختلاف حساب SSH با مسیر فایل‌های راه‌انداز Robot 2 نیز روی Pi واقعی باید بررسی شود.
