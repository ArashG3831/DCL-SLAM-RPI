# راهنمای راه‌اندازی و کار با سامانه دو‌رباتی

این پوشه پیش‌نویس مستندات تحویل سامانه به دانشجوی بعدی است. محتوا بر پایه بسته فرمان‌های WSL و نسخه پشتیبان رایانه Robot 2 تهیه شده است. این پوشه فقط مستندات دارد و هنوز شامل کد اجرایی سامانه نیست.

این شاخه مستندات را نگه می‌دارد. فرمان‌های راه‌اندازی در README فرض می‌کنند بسته WSL در ادامه با ساختار WSL/ به مخزن افزوده شود.

## نکته مهم درباره نام پوشه Robot 2

نسخه پشتیبان Robot 2 در پوشه‌ای به نام **robot1** قرار دارد. این نام از محیط قبلی ربات به ارث رسیده و نام رباتی را که کد برای آن نوشته شده تعیین نمی‌کند. در مخزن نهایی، این محتوا باید زیر مسیر **robots/robot2/** قرار گیرد.

نسخه کد سمت Robot 1 در ورودی‌های بررسی‌شده وجود نداشت. بنابراین این راهنما فرمان‌های WSL مربوط به هر دو ربات را توضیح می‌دهد، اما جزئیات راه‌اندازی درون‌رباتی را فقط برای Robot 2 مستند می‌کند.

## راه‌اندازی سریع

۱. در ویندوز، WSL 2 و Ubuntu 24.04 را نصب کنید. ROS 2 Jazzy در بسته فعلی برای همین نسخه Ubuntu نصب می‌شود. دستور رسمی نصب **wsl --install -d Ubuntu-24.04** است. راهنماهای رسمی در [نصب WSL در مایکروسافت](https://learn.microsoft.com/windows/wsl/install/) و [نصب Ubuntu در WSL](https://documentation.ubuntu.com/wsl/latest/howto/install-ubuntu-wsl2/) آمده‌اند.

۲. Ubuntu را یک بار اجرا کنید و نام کاربری و گذرواژه لینوکس را بسازید. در PowerShell بررسی کنید که توزیع با نسخه ۲ اجرا می‌شود.

~~~powershell
wsl --list --verbose
~~~

۳. بسته کامل تحویل را در مسیر کوتاه و بدون تغییر ساختار پوشه‌ها روی میزکار ویندوز قرار دهید. از Ubuntu، نصب‌کننده فایل‌ها را اجرا کنید. نام کاربری ویندوز را با نام واقعی پوشه زیر C:\Users جایگزین کنید.

~~~bash
bash "/mnt/c/Users/<نام‌کاربری ویندوز>/Desktop/<پوشه تحویل>/WSL/install_bundle_files.sh"
source ~/.bashrc
bash ~/install_robot_handoff_dependencies.sh
~~~

نصب‌کننده فعلی وابستگی‌ها، فرمان proxy_test را بدون شرط اجرا می‌کند. بنابراین برای استفاده از همین نصب‌کننده باید شنونده v2rayN روی ویندوز در دسترس WSL باشد. جزئیات در [راه‌اندازی ویندوز و WSL](docs/01_windows_wsl_setup.md) آمده است.

۴. در WSL، کلید SSH جداگانه برای هر ربات بسازید و کلید عمومی را با روش تأییدشده آزمایشگاه روی همان ربات نصب کنید. گذرواژه‌ها و کلیدهای خصوصی نباید وارد مخزن شوند.

~~~bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_robot1
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_robot2
ssh robot1 hostname
ssh robot2 hostname
~~~

۵. برای ورود دوباره هر دو ربات به پرتال اینترنت دانشگاه، فرمان زیر را اجرا کنید و شناسه و گذرواژه دانشگاه را در ورودی تعاملی وارد کنید.

~~~bash
~/robot_wifi_login
~~~

۶. برای مشاهده نقشه‌ها، فرمان زیر را اجرا کنید. فرمان، نشانی محلی رایانه و نشانی قابل استفاده از تلفن همراه روی همان شبکه بی‌سیم را چاپ می‌کند.

~~~bash
~/robot_pair_view
~~~

۷. اجرای Robot 2 با فرمان زیر آغاز می‌شود.

~~~bash
~/robot2_visual
~~~

بستن پنجره WSL یا RViz به‌تنهایی اجرای درون‌رباتی را متوقف نمی‌کند. پس از پایان کار، فرمان توقف را جداگانه اجرا کنید.

~~~bash
~/robot2_stop
~~~

۸. پس از پایان و نهایی‌شدن فایل‌های اجرا، فرمان ویدئو خروجی را می‌سازد. این فرمان به FFmpeg ویندوزی و اصلاح مسیرهای مختص هر کاربر نیاز دارد.

~~~bash
~/robot_pair_video
~~~

## فرمان‌های آماده

| فرمان | کارکرد |
|---|---|
| **~/robot1_visual** | آغاز اجرای Robot 1 از راه SSH و راه‌اندازی پل مشاهده محلی در WSL |
| **~/robot1_stop** | درخواست توقف صریح اجرای Robot 1 |
| **~/robot2_visual** | آغاز اجرای Robot 2 از راه SSH و راه‌اندازی پل مشاهده محلی در WSL |
| **~/robot2_stop** | درخواست توقف صریح اجرای Robot 2 |
| **~/robot_pair_view** | راه‌اندازی داشبورد نقشه برای رایانه و تلفن همراه |
| **~/robot_pair_video** | دریافت اجراهای نهایی‌شده و تولید ویدئو و گزارش |
| **~/robot_wifi_login** | ورود تعاملی هر دو ربات به پرتال اینترنت دانشگاه |
| **proxy_on**، **proxy_off**، **proxy_test** | فعال‌سازی، غیرفعال‌سازی و بررسی پراکسی WSL |

در فرمان‌های robot1_visual و robot2_visual، RViz به‌طور پیش‌فرض غیرفعال است. این فرمان‌ها اجرای ربات، پل Zenoh و گزارشگر زنده را راه می‌اندازند. داشبورد تلفن همراه مسیر مشاهده پیش‌فرض است. رفتار هر فرمان در [فرمان‌های WSL و شبکه](docs/02_wsl_helpers_and_network.md) توضیح داده شده است.

این متن پیش‌نویس مستندات است و نیازمند بازبینی و تأیید نهایی نویسنده سامانه است. پیش از انتشار باید موارد باز در سند کالیبراسیون تکمیل و مسیرهای ورود SSH روی سخت‌افزار تأیید شوند. هیچ‌یک از فرمان‌های ربات در این بازبینی اجرا نشده‌اند.
