# ساختار پیشنهادی مخزن و پاک‌سازی انتشار

## وضعیت ورودی‌های بررسی‌شده

کد و مستندات WSL در بسته‌ای روی میزکار ویندوز با ساختار WSL/ قرار دارند. نسخه پشتیبان Pi در پوشه‌ای با نام robot1 قرار دارد، اما فایل اجرای فعال، فایل‌های راه‌انداز ROS و تنظیم‌های آن Robot 2 را هدف می‌گیرند. مسیر نام‌گذاری‌شده باید هنگام آماده‌سازی مخزن به robots/robot2/ تبدیل شود؛ فایل‌ها در ممیزی جابه‌جا یا ویرایش نشده‌اند.

پوشه خانگی ربات شامل یک درخت Git پر از فایل‌های تغییرکرده و خروجی‌های تولیدشده است. درون cooperative_migration_source/.git نیز فراداده Git وجود دارد که HEAD آن در نسخه کپی‌شده خواندنی نبود. بنابراین این مجلد تودرتو را نباید خودکار به‌عنوان تاریخچه معتبر مخزن تلقی کرد. درخت اصلی پوشه خانگی را نیز نباید با git add . به مخزن تحویل تبدیل کرد.

## ساختار پیشنهادی

~~~text
robot-system-handoff/
~~~

پوشه مستندات فعلی همین الگو را برای README.md و docs/ آماده می‌کند. پوشه‌های wsl/ و robots/ عمداً در این بسته ساخته نشده‌اند، چون درخواست این مرحله مستندات بوده است و کد باید بدون ویرایش باقی بماند.

## فایل‌هایی که باید پس از انتخاب نسخه فعال وارد شوند

- فرمان‌های WSL و نصب‌کننده‌هایی که در WSL/install_bundle_files.sh کپی می‌شوند.
- دو بسته ROS سمت WSL در WSL/source/ که داشبورد، گزارشگر و ابزار ویدئو به آن‌ها وابسته‌اند.
- قالب‌های example و template، بدون کلید خصوصی، نام کاربری واقعی یا گذرواژه.
- فایل راه‌انداز فعال Robot 2 و بسته‌های پروژه‌ای که این فایل فراخوانی می‌کند.
- پروفایل‌های واقعی SLAM و Nav2 که راه‌انداز از بسته نصب‌شده بارگذاری می‌کند.
- فایل تنظیم روتر Zenoh مورد استفاده Robot 2 و دستور نصب نسخه پل 1.10.0.
- کد منبع نسخه سفارشی SLAM Toolbox و وابستگی‌های ضروری آن، همراه با منشأ و نسخه دقیق.
- فایل فهرست وابستگی‌ها با شناسه‌های نسخه مشخص؛ هر وابستگی بالادستی باید با نسخه‌ای که واقعاً ساخته و اجرا شده تطبیق داده شود.

کد سمت Robot 1 تا یافتن نسخه معتبر آن نباید با کد Robot 2 پر شود. فایل‌های منبعی که تنها برای Webots، تحلیل آفلاین یا آزمایش‌های قدیمی هستند باید پس از ردیابی ارجاع فایل راه‌انداز فعال جدا شوند؛ نام فایل به‌تنهایی برای نگه‌داشتن یا حذف کافی نیست.

## فایل‌ها و داده‌هایی که نباید به مخزن GitHub وارد شوند

- پوشه‌های build/، install/ و log/ تمام فضاهای کاری
- __pycache__/، فایل‌های *.pyc، .pytest_cache/، .cache/ و محیط‌های مجازی Python
- گزارش اجرای ROS، فایل‌های ثبت داده، داده‌های خام حسگر، آرایه‌های NPZ، فیلم‌ها، خروجی‌های نقشه و پوشه‌های results/
- نسخه‌های پشتیبان با پسوندهایی مانند .bak، .orig و نام‌های زمان‌دار، مگر آنکه پس از بررسی به‌عنوان منبع ضروری انتخاب شوند
- فایل‌های پوشه خانگی مانند .ssh/، تاریخچه فرمان‌ها، تنظیم‌های شخصی Shell، کلیدهای خصوصی و کلیدهای عمومی منتسب به یک دانشجو
- فایل فشرده robot1.rar تا محتوا و حساسیت‌های آن جداگانه بررسی نشده باشد
- .wslconfig رایانه شخصی و نمونه portproxy شامل IP پویای WSL
- مسیرهای خروجی ویدئو که نام کاربری Asus را در مسیر ویندوز تثبیت کرده‌اند

نمونه مواردی که می‌توان در .gitignore مخزن نهایی افزود، در زیر آمده است. این متن فقط پیشنهاد است و در هیچ فایل پیکربندی موجود نوشته نشده است.

~~~gitignore
**/build/
**/install/
**/log/
**/__pycache__/
**/.pytest_cache/
**/.cache/
**/.venv/
**/venv/
*.py[cod]
*.db3
*.mcap
*.bag
*.npz
*.mkv
*.mp4
.env
*.key
id_ed25519*
~~~

الگوهای *.py یا test/ را نادیده نگیرید؛ آن‌ها ممکن است کد منبع و آزمون‌های نگه‌داشتنی باشند. داده‌های اندازه‌گیری منتخب را در صورت نیاز به‌صورت نمونه کوچک، پاک‌سازی‌شده و با توضیح منشأ نگه دارید.

## بازبینی پیش از نخستین ثبت تغییرات

۱. یک مخزن جداگانه برای تحویل بسازید و پوشه کپی کامل پوشه خانگی ربات یا ریشه پروژه پایان‌نامه را مستقیماً به آن تبدیل نکنید.
۲. مسیر Robot 2 را به نام روشن robots/robot2/ منتقل کنید و توضیح هویت Robot 2 را نزدیک آن نگه دارید.
۳. مسیر Robot 1، حساب‌های SSH و همه IPهای ثابت را روی شبکه آزمایشگاه تأیید کنید.
۴. مسیرهای Asus را از ابزار ویدئو قابل تنظیم کنید یا دستور دقیق تغییر آن‌ها را مستند کنید.
۵. نسخه‌ها و شناسه‌های ثبت تغییرات ROS 2، Zenoh bridge، Nav2، SLAM Toolbox و بسته‌های محلی را ثبت کنید.
۶. از نبود گذرواژه، کلید خصوصی، تاریخچه پوسته و اطلاعات ورود شبکه بی‌سیم در کنار فایل‌های شخصی اطمینان حاصل کنید.
۷. برای هر فایل پیکربندی، فایل راه‌انداز فراخوانده‌شده و مسیر نصب‌شده‌ای را که در زمان اجرا خوانده می‌شود ثبت کنید.
۸. راه‌اندازی را روی WSL تازه و هر دو Pi واقعی طبق مستندات انجام دهید و موارد ناموفق را پیش از انتشار اصلاح کنید.

شاخه مستندات فقط README و فایل‌های راهنما را اضافه می‌کند. کد نهایی Robot 2 و بسته فرمان‌های WSL وارد این تغییر نمی‌شوند و باید پس از پاک‌سازی و تعیین نسخه معتبر، جداگانه به ساختار پیشنهادی افزوده شوند.
